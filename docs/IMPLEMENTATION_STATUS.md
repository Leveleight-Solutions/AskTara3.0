# Asktara implementation status

The current source implements **Agent Studio**, the travel-agent proposal workflow now deployed to Railway. Home and primary navigation open `/studio`; the earlier consumer concierge remains separate at `/chat` and `/trips`. See [Agent Studio workflow](AGENT_STUDIO.md) for requirements, API connections and boundaries. The configured Railway target and current deployment are recorded in [deployment documentation](RAILWAY_DEPLOYMENT.md).

## Agent Studio

| Capability                   | Current implementation                                                                                                                     | Boundary                                                                                                                                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Natural client brief         | Free text, pasted email/PNR, screenshot/PDF, public tour link and opt-in dictation; preview extracted text before saving                   | OpenAI is configured in the current project. Raw files are processed in memory; saved reviewed text is private. A fresh checkout without a key retains manual editing and simple local intake.               |
| Brief review                 | Known facts, completeness indicator and relevant missing questions; qualification can be skipped                                           | Review extracts a draft route without supplier searches or activity generation. Unknown facts are not replaced with defaults.                                                                                |
| Route structure              | Editable destinations, nights, arrival/departure dates, onward transport and neighbourhoods; drag/up/down ordering and fixed arrival dates | Up to 20 stops, 120 nights per stop and 365 total nights. Conflicting dates require correction. Material route changes invalidate acceptance and require affected service review.                            |
| Explicit acceptance          | Accept the route before supplier searches or recommendation research                                                                       | Approval concerns the proposal structure; it is not booking consent.                                                                                                                                         |
| Existing arrangements        | Manual hotel/flight/tour/cruise/transfer/insurance items; explicit extraction from saved sources yields candidates                         | Imported candidates start unselected and require agent review. Private booking references remain outside client output.                                                                                      |
| Supplier suggestions         | Flight and hotel quote search through the same LiteAPI key; explicit quote selection creates a proposal item                               | The configured LiteAPI connection stays sandbox. Searches support confirmed adult-only parties; reviewed family quotes are entered manually. No reservation, ticket, payment or policy is created by Studio. |
| Personalised recommendations | Optional sourced activity or food lists for selected destinations, with stated interests and requirements                                  | New recommendations start unselected. The agent chooses what reaches the client proposal. No fixed morning/lunch/dinner schedule or unsupported suitability guarantee.                                       |
| Client context               | Private client-name/context history and links to previous workspaces                                                                       | Prior context is reused deliberately. New trips begin with unknown adult/child counts; this is lightweight history, not a full CRM or cross-agency learning system.                                          |
| Agency settings              | Branding, contact details, custom qualification questions, price validity and GDS format hint                                              | Amadeus/Sabre/Galileo selection assists text interpretation; it does not activate a GDS/NDC connection.                                                                                                      |
| Pricing                      | Itemised or explicit package price, private acquisition costs and commercial allowances; labelled agent insurance estimates                | No mixed-currency total, invented insurer premium formula or automatic legal card-surcharge rule. Production insurer quoting still needs an approved API.                                                    |
| Client proposal              | Branded private preview, PDF and explicit publication to a revocable read-only snapshot                                                    | Only selected reviewed items and selected recommendations appear. Chat, imports, private context, references, costs and margins are excluded. Package mode hides component prices.                           |
| Price validity               | Configurable validity, default 48 hours, with reconfirmation messaging for aged prices                                                     | The proposal stays viewable after validity expires. Republish does not make an old supplier quote fresh. No client comments, acceptance, payments or automatic email sending.                                |

A real Railway browser check passed for a freshly authored 28-day Paris–Berlin–London brief: 27 nights, explicit party/budget/preferences, concise GPT-6 Astra intake, route acceptance and persistence after reload, with no supplier search or booking during intake. Detailed release checks and their scope belong in [verification](VERIFICATION.md).
